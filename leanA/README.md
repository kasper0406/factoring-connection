# leanA: a conditional Lean 4 formalisation of Theorem A / RA / P

This Lake project formalises the main theorem chain of `paper2/main.tex`, cited as [pp] by `\label` name.
- **Theorem A**: rigorous Las Vegas factoring in L_N[1/2, (1+θ)/√2 + o(1)], and in L[1/2, c] for every c > 1/√2.
- **Theorem RA**: L[1/2, √((1+√2)θ)].
- **Corollary P**: L[1/2, o(1)].
- **Theorems U and DL**: assembly steps only.

It is **conditional**. Its inputs are:
- four **published theorems**, stated as `Prop`s and passed as hypotheses;
- two **internal moment hypotheses**, the project's first- and second-moment theorems;
- an explicit **cost-accounting interface** for the algorithm.

Everything else in the chain is proved in Lean. There are no `axiom` declarations and no `sorry` in the proof layer.

The status table and the checker results are in `../notes/leanA_results.md`.

## Toolchain

- Lean `leanprover/lean4:v4.35.0` (`lean-toolchain`) and Mathlib tag `v4.35.0` (the commit is pinned in `lake-manifest.json`).
- Why this choice:
  - It matches leanprover/comparator HEAD, whose `lean-toolchain` is v4.35.0. Comparator has been merged into core Lean 4.35 as `lake comparator` / `lake check`.
  - It matches the existing `../lean/` project.
  - openai/math pins v4.34.1 and openai/PrimeGaps186 pins v4.34.0-rc2. We use 4.35.0 because its toolchain bundles every external checker: `leanchecker-paranoid`, `lean4lean`, `nanoda_bin`, `con-leche` and `con-ron`.

## Build and check

On the host (macOS), with `~/.elan/bin` on PATH:

```sh
cd leanA
lake exe cache get          # prebuilt Mathlib
lake build                  # builds LeanA and Challenge
lake env lean AxiomCheck.lean   # every line: [propext, Classical.choice, Quot.sound]
python3 scripts/gen_challenge.py && git diff --exit-code Challenge.lean comparator.json AxiomCheck.lean
```

Sandboxed paranoid check in Linux. `lake comparator` needs bubblewrap, which needs Linux namespaces. We use Docker Desktop:

```sh
docker build -t leana-checker leanA/docker
leanA/docker/check.sh       # from the repository root; log in leanA/docker/last_check.log
```

`check.sh` copies the sources into a fresh Ubuntu 24.04 container and fetches the Mathlib cache. It builds `LeanA` and `Challenge` from source, scans for `sorry`, `axiom` and `opaque` declarations, and runs `#print axioms`. It then runs `lake comparator --paranoid`, which does the following:
- builds and exports `Challenge` and `LeanA` inside bubblewrap, with an empty network namespace;
- checks that every theorem in `comparator.json` has the same statement in both;
- checks that every constant the statements use is identical in both;
- checks that the axioms are within `propext`, `Quot.sound` and `Classical.choice`;
- replays the solution through Lean's kernel, `leanchecker-paranoid`, `lean4lean`, Nanoda, `con-leche` and `con-ron`.

Docker's seccomp, AppArmor and masked-`/proc` confinement are relaxed only so that bubblewrap can create its namespaces. Negative controls were run on a toy project: a changed definition and an extra axiom were both rejected.

## What is assumed

See the docstrings in `LeanA/Hypotheses.lean`.

PUBLISHED INPUT:
- `BrunTitchmarsh`: Montgomery–Vaughan 1973, Thm 2.
- `RosserSchoenfeld`: Rosser–Schoenfeld 1962, Cor. 1 and 3.
- `CEP`: Canfield–Erdős–Pomerance 1983.
- `LenstraPomerance`: Lenstra–Pomerance 1992. It is attached to the cost model's `TLP`.

INTERNAL HYPOTHESIS:
- `FirstMoment`: [pp] Thm thm:FM.
- `SecondMoment`: [pp] Thm thm:LD ("LD*").

Both are statements about the concrete filtered count `Params.countN` under the concrete field law.

COST-MODEL INTERFACE (`CostInterfaceA`, `CostInterfaceRA`): each field is one displayed claim of [pp] about the algorithm. The fields cover:
- Lemma reject;
- Prop. select(ii);
- the M_rows bound;
- the trial cost;
- Prop. BS;
- Prop. lv6;
- the factor-tree accounting of §uniform;
- the recursion inequality of Thm RA.

None of them mentions the final exponent. The trial-success probability is tied to the concrete descent probability, so the relation supply enters through the proved `descent_supply` and is not assumed.
