Context: we want to decide, for an RSA-like N=pq with UNKNOWN factors, the predicate U(K) := [gcd((K-1)!, N) = 1] (equivalently: K <= least prime factor), ideally faster than computing (K-1)! mod N. Binary search on U gives the least prime factor. We do NOT need the factorial value, only unit/nonunit.

For Tal's paper: give a precise technical summary of the algorithm: every identity used (Jacobi sums, Gauss sums, reconstruction steps, recursive reductions), each step's cost, and for EACH step state exactly what it requires to know: the prime p itself, the factorization of p-1 or of some auxiliary integer, a primitive root / generator, multiplicative characters of known order, a field structure (division), etc. Then: which steps survive if computing modulo a composite N with unknown factorization (work in Z/NZ, treat failed inversions as factor discoveries)? Where exactly does the argument break? Is there any sub-step that computes a product of the form prod_{j in S} (x - j) or a factorial-like quantity modulo N with cost below sqrt(K)? Be concrete: name lemma/section numbers.

For BGS and Harvey/HH: extract exactly the operation that is batched (e.g., multipoint evaluation of prod (x+i) over a progression; baby-step/giant-step on polynomial matrices; Harvey's use of the structure of N ≡ ... and lattice/"Lehman-like" steps), the cost in terms of K or N, and what part of the method depends only on N (unknown factors) vs on hypotheses.

Then do original thinking: propose up to 3 concrete ideas for answering ONLY the unit predicate U(K) (or a weaker statement, e.g., "the interval [A,B) contains a divisor of N") more cheaply than the factorial value, e.g., using that a unit test only needs the product modulo an unknown prime to be nonzero, randomization, character sums whose evaluation is explicit from N alone, or polynomial identities in Z/NZ[x].
