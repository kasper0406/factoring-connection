# Rules for all agents working in this repo

Project root: `/home/knielsen/code/factoring-connection`. Read `BRIEF.md` fully, especially Sections 2, 5, and 6. Use `.venv/bin/python`, which has sympy, gmpy2, python-flint, numpy, and pytest. Do not pip-install packages into the system Python; adding a package to `.venv` with `uv pip install --python .venv/bin/python X` is fine.

1. **Exact arithmetic only.** Floating-point is allowed only for plots or fits.
2. **No leakage.** A candidate algorithm (anything under `src/candidates/` or any function documented as "operational") receives only `N`, public config, and a seed. It never calls sympy/flint factorization or primality-with-factor routines, and never uses `p`, `q`, `phi`, or group orders. Factor-aware code goes under "diagnostic" or "harness", is named as such, and is never imported by operational code. Where a candidate needs a primality test, note that you used one.
3. **Every nonunit is output.** Whenever you invert modulo N, check `gcd` first. When you record a factor discovery, also classify it: STRUCTURAL (explained by the mechanism) or ACCIDENTAL (e.g. divisibility by a small integer that was tested directly, or a random gcd hit whose probability is about 1/p). Report the rate of each separately, and compare against the null expectation of random gcd hits.
4. **Instrument costs.** Count ring ops (by kind), gcd calls, max operand bits, max materialized degree, stored coefficients, circuit nodes, and extension degree. Report raw counters against both `n = log2 N` and the hidden structural parameters (`p`, `q`, `sqrt N`). Watch for anything that grows like a hidden factor.
5. **Status labels.** Every claim in notes carries one of: `proved`, `experimentally supported`, `conjectured`, `refuted for this model`, `not yet tested`. Proofs go in the notes. Do not claim novelty: write "no prior formulation found by us" at most, and leave novelty judgments to the orchestrator.
6. **Reproducibility.** Use seeded instance generation (shared generator in `src/common/instances.py` once it exists). Store raw results as JSONL under `experiments/raw/`, configs under `experiments/configs/`, and the exact commands in the notes.
7. **File ownership.** Stay inside your own files; see the table in `STATUS.md`. Do not edit other agents' files. If you need a helper that lives in another owner's area, copy it into your own module.
8. **Don't inflate.** Toy-size factoring successes are correctness checks only. A mechanism whose cost is polynomial in `p` (or in `sqrt N`, or in a degree near `p`) is NOT polynomial. Say so plainly.
9. **Write candidate cards** using the template in BRIEF Section 4 for every serious mechanism you try, including the ones that fail. A precise, scoped obstruction ("in model M, operation X needs dimension ≥ f(p) because ...") is a valuable output.
10. **Final message.** End with a concise summary (≤ 400 words): what you built, proved results, experimental results with key numbers, refuted mechanisms with their scope, and the single most promising open question. Add the file paths.
